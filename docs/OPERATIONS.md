# 备份与恢复

## 需要分别保存的材料

- 数据库备份包含证书版本、加密的私钥与凭据、任务、审计和用户记录，仍属于敏感数据。
- `.env` 中的 `ENCRYPTION_KEY` 是解密已有数据的主密钥，必须单独、安全保存。
- 部署配置、版本源码、主机侧云效接入配置及原有 Nginx 配置，也需要纳入恢复方案。

不要把数据库备份和主密钥合并成公开归档。建议将恢复材料存入受控的密码库或加密离线存储。Windows 文件需检查 ACL；Unix 文件及备份目录应仅对管理员开放。

## 创建备份

在源码目录执行：

```bash
python3 ops/backup.py
```

脚本通过本项目的 db 服务执行 `pg_dump -Fc`，创建权限为 0600 的文件并验证备份目录可读。文件名使用 UTC 时间，保存到 `backups/`。失败文件标记为 `.incomplete`，不作为完成备份使用。

在线 `pg_dump` 提供一致性数据库快照；升级和重大变更前建议先暂停 worker、等待活动部署结束，再备份。脚本不会自动删除备份；保留、异地复制、定期执行及恢复演练由部署者配置。

## 在新环境恢复

以下操作应在独立的新恢复目录、空数据库卷中进行。不要指向仍在运行的生产安装。

1. 下载与备份兼容的版本源码。
2. 执行 `python3 ops/init.py` 生成新环境的数据库密码。
3. 在本机编辑 `.env`，将 `ENCRYPTION_KEY` 改为原环境的密钥，并设置恢复入口 `PUBLIC_URL`。不要复制错误的旧数据库主机地址。
4. 只启动数据库：

```bash
docker compose up -d db --wait
```

5. 将备份放入本机受保护目录后执行：

```bash
python3 ops/restore.py backups/your-backup.dump --confirm-empty
```

恢复脚本要求 web、worker 未运行且 public schema 为空；它不删除已有对象，遇到错误时回滚整个恢复事务。

6. 先仅启动 web：

```bash
docker compose up -d web --wait
```

使用**备份中的管理员密码**登录；新 `.env` 的初始密码不会覆盖恢复的用户。核对证书、凭据和任务。恢复的自动化开关及未完成任务会继续保留，恢复环境连接真实云账号前，应检查并暂停不应执行的自动化和任务。

7. 核对入口与实际业务状态，决定何时启动 worker：

```bash
docker compose up -d worker --wait
```

数据库恢复不会自动回退外部云产品或 Nginx 的证书状态；恢复后应重新检查服务实际证书。隔离演练环境应限制外部网络访问，避免重新执行真实部署。

## 密钥与凭据轮换

管理员改密与 Fernet 主密钥不同。不要重新运行初始化来“重置”主密钥。当前没有在线主密钥轮换工具，直接改 `ENCRYPTION_KEY` 会导致旧数据无法解密。

云账号、SSH 与云效令牌的轮换应先在对应服务创建新凭据、核对权限，再更新控制台并验证，最后撤销旧凭据。云效主机接入配置在轮换目标令牌后需要同步更新。

## 云部署提交结果不明

云 API 的响应可能在云端已接受请求后丢失。系统会在写入前保存提交标记；超时、异常或进程中断后，重试原任务先核对目标实际 TLS 指纹。已经生效的部署可以恢复完成，不会再次上传或提交。

如果实际证书尚未匹配，原任务停止重发并要求人工核对。先检查云控制台的证书、绑定和传播状态，也可等待后重试核对。只有确认没有生效、资源状态符合预期后，才通过新的部署预览创建任务。修复权限或网络后直接重试旧任务，也不会跳过这一保护。

结果不明期间，该目标的新自动部署会暂停，包括上传触发、定时调度和已经排队的自动任务；等待超过 24 小时也不会绕过。人工核对后重试原任务完成确认，或通过新的手动部署验证成功，才允许后续自动部署。自动化开关不会被静默改写。

这项保护以停止不确定写入为代价减少重复提交，不能代替各产品的真实故障注入验收或云端事务。GA 原有 ClientToken 与上传编号检查点继续保留。

业务健康检查 URL 应直接返回 2xx；不会自动跟随 3xx 重定向。请填写最终 HTTPS 地址。
