# 云效部署 Nginx

适用于控制台不能直接 SSH 到目标机、但云效能够执行主机任务，且目标机可访问控制台 HTTPS 的环境。当前实现面向云效中央版 OpenAPI，其他版本需要核对接口兼容性。

## 准备

- 单台目标 Linux 主机，Python 3、OpenSSL 及已有 Nginx 服务。
- 证书文件与私钥文件位于同一目录，使用绝对路径。
- 专用证书部署流水线、只包含预期目标的主机组；避免同时承担业务构建与任意发布操作。
- 云效个人访问令牌：读取流水线配置、触发与查询运行实例所需权限。日常运行无需修改其他流水线。

## 配置流程

1. 在控制台创建“云效个人访问令牌”凭据，填写自己的组织 ID、令牌与测试流水线 ID。“测试连接”只读取指定流水线。
2. 在云效创建主机执行任务，将 [yunxiao-task.sh](../deploy/yunxiao-task.sh) 的内容放入该任务。流水线接收 `CERTOPS_JOB_ID` 和 `CERTOPS_ATTEMPT_ID` 两个变量，不在变量中放入私钥或主机令牌。
3. 在控制台创建“云效流水线 / Nginx”目标，填写自己的流水线 ID、机器标识、域名、证书及私钥路径，并绑定证书。同一物理机与其 VIP 不应重复登记为两台主机。
4. 点击“主机接入配置”。此操作校验流水线配置并轮换主机专用令牌；在没有执行中任务时操作。
5. 将界面返回的配置保存至目标主机 `/etc/certops/pipeline.json`，root 所有、0600。下载控制台 `/api/pipeline/client.py`，核对文件后安装至 `/usr/local/libexec/certops-pipeline.py`，root 所有、0750。
6. 核对配置中的 Nginx 检查命令、重载参数、SNI、本机探测地址、端口及可选 `ca_file`。不要直接套用与自己安装方式不同的路径。
7. 先使用“检查”验证回传与本机 TLS，再在测试目标上执行部署、确认新指纹并验证回退。

## 执行与回退

客户端领取指定目标、版本与有效期的任务，下载匹配的证书和私钥，验证后切换。原文件保存在同目录的 `.certops-<目标ID>/versions/original-*`，原路径转为符号链接，通过一个 `current` 指针成对切换证书与私钥。

Nginx 检查、重载或 TLS 验证失败时，客户端尝试恢复原指针、重载并验证旧证书。私钥文件权限为 0600。“检查”任务不允许下载私钥。

控制台同时核对云效运行结果与目标认证的本机回传。流水线配置发生变化后，需要重新核对接入配置。控制台可从目标本机结果验证 TLS，无需直接访问机房 TLS 端口。

主机令牌属于敏感凭据，不能提交到流水线 YAML、仓库或工单。轮换后应同步更新主机 root 配置。目标主机权限、主机组范围及业务健康检查由部署者维护。
